## 2. システム論理構成

### 2.1 ランタイム（1次製品）

```
┌─────────────────────────────────────┐
│           ユーザー（ブラウザ）         │
└─────────────────┬───────────────────┘
                  │ HTTP
                  ▼
┌─────────────────────────────────────┐
│  Streamlit  app_japan_tour.py        │
│  · セッション状態 (messages)          │
│  · システムプロンプト（日・韓）        │
│  · OpenAI Chat Completions           │
└─────────────────┬───────────────────┘
                  │ HTTPS / JSON
                  ▼
┌─────────────────────────────────────┐
│         OpenAI API                   │
│  · gpt-4.1-mini（対話・翻訳）        │
└─────────────────────────────────────┘
```

### 2.2 オフライン・データパイプライン

```
AI Hub 原本（手動 / aihubshell）
        ↓
data/raw/tour_knowledge.csv
        ↓  tour_preprocess.py (pandas)
data/processed/tour_knowledge.jsonl
        ↓（将来）
埋め込み・ベクトルストア・RAG チェーン
```

### 2.3 ランタイム（任意 — HTML フロント + Django）

ブラウザは `frontend/` の静的ファイルを Django が配信し、チャットは `/api/chat/` へ POST する。

```
[ユーザーブラウザ]
        ↓ HTTP
[Django — backend/manage.py · config · tour_api]
  · ルート `/` → `frontend/home.html`
  · チャット画面 → `frontend/chat.html`（ルーティングは実装に従う）
  · `/api/health/`, `/api/chat/`
        ↓ HTTPS
[OpenAI API]
```

## 4. 画面・UI 設計（Streamlit）

### 4.1 画面領域

| 領域 | 構成要素 |
|------|----------|
| メイン | タイトル、キャプション、チャット履歴、`st.chat_input` |
| サイドバー | 利用法（日・韓）、応答言語ラジオ、AIHUB キー案内、対話リセットボタン |

### 4.2 状態モデル

| キー | 型（論理） | 説明 |
|------|------------|------|
| `messages` | list | `role`（user/assistant）、`content`、任意 `translated_ko` |

### 4.3 処理シーケンス（メッセージ入力時）

1. ユーザー入力を `messages` に追加する。  
2. `chat_with_openai`: システムプロンプト + 既存 user/assistant + 現在の user → 完了 API。  
3. 応答言語が「日本語」のとき `translate_to_korean` を呼び、UI に翻訳ブロックを表示する。  
4. `messages` に assistant 項目を保存する（翻訳は `translated_ko`、次ターンのプロンプトは原文中心）。

## 6. データ設計

### 6.1 ディレクトリ

```
data/
  raw/
    tour_knowledge.csv    # 入力（推奨スキーマは DATA_PREPROCESSING.md）
  processed/
    tour_knowledge.jsonl  # 出力（1 行 = 1 オブジェクト）
```

### 6.2 JSONL レコード（論理）

前処理スクリプトは CSV に存在する列のみを直列化する。最低 `question_ja`, `answer_ja`；任意で `id`, `category`, `area`, `answer_ko`。

## 7. エラー・例外処理（基本）

| 状況 | 動作 |
|------|------|
| `OPENAI_API_KEY` なし | 警告表示、チャット時は API エラーメッセージ |
| `tour_knowledge.csv` なし | `FileNotFoundError` と案内メッセージ |
| 必須列欠落 | `ValueError` と欠落列名の表示 |

## 8. セキュリティ設計（基本）

- キーは環境変数のみ使用する。  
- ログにユーザー質問・応答を残す場合は**個人情報・センシティブ方針**の検討（運用段階の課題）。

## 9. 拡張ロードマップ（基本設計レベル）

| 段階 | 内容 |
|------|------|
| PROFILE-1 | 会員登録・顧客情報（性別・性格・趣味・出身地・韓国への関心・予算・航空出発・到着・ホテル予約・帰国時刻等）および**仁川空港・宿泊**基準の観光地距離順推薦 |
| TRANSIT-1 | **空港 → 宿泊**初動線:**最短時間**・**最低コスト**・**乗り換え最小**目的別（または複数案比較）経路案内；地図・公共交通 API 連携時はルール・キャッシュ・出典メタデータ設計 |
| RAG-1 | `tour_knowledge.jsonl` またはベクトル DB を `app_japan_tour.py` 応答前の検索に接続 |
| RAG-2 | `tour_knowledge` 埋め込み検索を `prepare_context` に接続 |
| 評価 | `evaluation/` に Japan Tour 用 `test_dataset.json` と正解セットを追加 |
| デプロイ | Streamlit Community Cloud / コンテナ / リバースプロキシ等は別アーキテクチャ設計 |
