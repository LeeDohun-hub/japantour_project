## 3. 챗봇 무응답 버그 3종 수정

### 현상

챗봇에서 `"경복궁 한복대여 어디서해?"` 입력 시 입력값만 지워지고 아무 반응 없음.

### 원인 추적 (3단계)

**① 백엔드 — 지역 코드 미탐지**

`_LEGACY_AREA_CODE_HINTS`에 `"경복궁"`이 없음 → `area_codes = []` → VisitKorea 관광지 검색 skip.  
카테고리가 `"culture"`이면 `PLACES_TYPE_MAP`에도 없어 Places API도 skip → 카드 없음.  
LLM은 호출되지만 empty reply 가능성.

**② 백엔드 — 예외 시 HTML 500 반환**

`run_chat()`에 try-except 없음 → 예외 발생 시 Django가 HTML 500 반환 → `res.json()` 파싱 실패 → `data = {}`.

**③ 프론트엔드 — 빈 버블 생성**

`displayReply = ""` AND `extra = ""` → `appendBubble("assistant", "", "")` → "Guide" 레이블만 있는 거의 투명한 버블 → 사용자 눈에 무반응처럼 보임.

### 수정

| 파일 | 변경 내용 |
|------|----------|
| `src/chain/router.py` | `_LEGACY_AREA_CODE_HINTS`에 서울 주요 랜드마크 추가 (경복궁, 광화문, 북촌, 인사동, 창덕궁, 덕수궁, 경희궁, 남산, 한옥마을, 종로, 이태원, 동대문) → 모두 area code `"1"` (서울) |
| `backend/tour_api/views.py` | `run_chat()` 호출부를 try-except로 감쌈. 예외 시 JSON `{"reply": "...", "detail": "..."}` status 500 반환. `reply_language`에 따라 일본어·한국어 에러 메시지 분기 |
| `frontend/app.js` | `displayReply`와 `extra` 모두 빈 문자열일 때 언어별 fallback 메시지를 `appendBubble`로 표시 |

## 4. JS SyntaxError 수정 (`Unexpected token '*'`)

### 현상

브라우저 콘솔: `Uncaught SyntaxError: Unexpected token '*'`  
챗봇 입력 시 입력값이 지워지고 아무 응답 없음 (JS 파일 전체 실행 불가).

### 원인

`frontend/app.js` 322행 — `renderGyeonggiEventCards()` 함수 닫는 `}` 다음에 JSDoc 주석 시작 `/**`가 누락된 채로 `*`로 시작하는 줄이 있었음.

```javascript
// 문제 코드 (322행 이후)
}

 * 항공편 / 공항 카드 HTML 생성   ← /** 없이 * 로 시작 → SyntaxError
 * @param ...
```

### 수정

`frontend/app.js` — `/**` 추가:

```javascript
}

/**
 * 항공편 / 공항 카드 HTML 생성
```

## 7. 배운 것 / 이해한 것

### 지리적 실현 가능성과 반경 필터

거리 반경(`NEARBY_SPORTS_MAX_KM`)만으로 "갈 수 있는 장소"를 정의하면 이동 시간을 무시하게 됨.  
고양시(KINTEX)와 잠실은 직선 26.7km지만 저녁 러시아워에는 1~1.5시간 소요.  
LLM에 거리뿐 아니라 시간 제약을 명시적으로 주입해야 일정 환각이 줄어든다는 것을 확인.

### JS SyntaxError는 파일 전체를 실행 불가로 만든다

`/**`가 없는 `*`로 시작하는 줄 하나 때문에 `app.js` 전체가 파싱 실패.  
증상이 "아무 반응 없음"이라 원인을 UI/백엔드 로직에서 찾기 쉽지만, 브라우저 콘솔의 `Unexpected token '*'`가 직접적인 단서.  
기능 추가 후 반드시 브라우저 콘솔 에러 여부를 먼저 확인해야 한다.

### 공공 API의 주소 표기 불일치

한국 공공데이터포털의 행사 정보 API는 일부 응답에서 "경기도 고양시..." 대신 "고양시..."처럼 광역단체명을 생략함.  
`_REGION_KEYWORDS`에 광역단체명(`경기`)만 등록하면 시군구명 직접 표기 데이터가 전부 누락됨.  
공공 API 사용 시 주소 표기 변동에 대비해 최소 시군구 단위까지 키워드를 등록해야 한다.

### 빈 응답 처리와 사용자 경험

백엔드가 빈 `reply`를 반환하고 카드도 없을 때, 프론트엔드가 `appendBubble("assistant", "", "")` 호출 → 시각적으로는 아무것도 표시 안 됨. 사용자는 서버 오류인지, 입력이 안 된 건지 구분 불가.  
빈 응답 조건을 명시적으로 체크하고 fallback 문구를 보여주는 것이 필수.  
`"죄송합니다, 응답을 생성하지 못했습니다"` 한 줄이 무응답보다 훨씬 나은 UX.

### 데이터 계층형 fallback 설계

K-pop 이벤트처럼 공공 API 커버리지가 낮은 도메인은 단일 소스만으로 결과를 보장할 수 없음.  
`전국행사 API (콘서트 필터) → 전국행사 API (전체) → DuckDuckGo 웹 검색` 3단계 fallback을 통해  
API에 데이터가 없는 날짜·지역에서도 유용한 정보를 제공할 수 있음.  
각 단계의 결과물을 동일한 `GyeonggiEvent` 자료구조로 통일해 렌더러를 재사용한 점도 중요.

## 8. 추가 업무 내용 (동일 일자 · Cursor 세션)

위 섹션 1~7은 Claude 작성 초안을 유지한다. 아래는 같은 날 이어서 반영한 변경이다.

### 8.1 Google Places — 랜드마크+서비스 질의 시 주변 검색 우선 문제

**현상:** GPS가 있으면 `shopping`/`food`/`leisure`가 `search_nearby` 결과만으로 조기 반환되어, 분류기 `keyword`(예: 경복궁 한복대여)와 무관한 상가만 나오거나, 주변 결과가 비어 있으면 텍스트 검색으로 넘어가지 않는 경우가 있음.

**수정 (`src/chain/router.py`):**

- `_places_use_text_search_first` / `_shopping_leisure_text_queries` 도입 — 지명·한복·대여 등 힌트가 있으면 **먼저 Text Search**, nearby는 그렇지 않을 때만 사용.
- nearby 결과가 **비어 있을 때**는 lodging이 아니어도 텍스트 검색으로 폴백.
- `_CLASSIFIER_SYSTEM`에 `경복궁에 한복대여점`·일본어 예시 등 **shopping + landmark+서비스** 키워드 규칙 보강.

### 8.2 일정(itinerary) — 워터밤 등 여름 페스가 참조에 안 잡히는 문제

**원인:** 일정용 가이드가 사실상 “전국공연행사 API에만 있는 행사만 일정에 넣기”에 가깝고, 웹 검색은 사용자 문장에 행사 키워드·연도가 없으면 **호출되지 않음**(위저드만으로는 트리거 누락).

**수정:**

- `src/api/web_search_client.py` — 여행 기간이 **6~9월**과 겹치는 `itinerary`는 웹 검색 실행, `워터밤 Waterbomb …` 전용 쿼리와 기존 쿼리 병합.
- `router.py` — 일정 프롬프트의 **행사·페스티벌** 규칙을 전국 API / Visit Korea / **웹 검색** 다중 출처로 명시.
- `_do_gyeonggi()` 내 K-pop용 `name_filter`에 `워터밤`, `waterbomb`, `festival`, `edm` 등 추가.

### 8.3 NOL·티켓링크 요청 — 인터파크 모바일 SSR 기반 공연 메타 수집

**요구:** 티켓링크·NOL 등에서 크롤링해 뮤지컬·콘서트·연극·클래식·전시·가족 등 카테고리별로 일정 참조에 넣기.

**판단:** `ticketlink.co.kr` 공연 메인은 **빈 `#app` + JS 번들** 위주 SPA로, 서버 HTML만으로는 목록 JSON이 없음. 인터파크는 **PC 장르** `tickets.interpark.com/contents/genre/{slug}`의 ProductList 임베드 JSON(장르당 ~80건) + **하위 키워드 통합 검색**(페스티벌·가요 등) + `__NEXT_DATA__` SSR을 병합. 워터밤처럼 메인·ProductList에 없는 공연은 `keyword=워터밤` 검색으로 보강.

**신규·변경 파일:**

| 파일 | 내용 |
|------|------|
| `src/api/ticket_platform_events_client.py` | 장르별 병렬 fetch, 기간·프로필 지역 스코어링, `fmt_ticket_platform_events` |

## 9. 추가로 배운 것 / 이해한 것 (Cursor 세션)

### Places: “좌표가 있으면 무조건 주변이 정답”은 아니다

같은 카테고리라도 **의도가 랜드마크+특정 서비스(한복 대여)**일 때는 주변 `type` 검색이 오히려 엉뚱한 POI를 채운다. 키워드 힌트가 있으면 **텍스트 검색을 먼저** 두는 쪽이 맞고, 주변 검색은 **결과가 있을 때만** 조기 반환하고 비어 있으면 텍스트로 넘기는 것이 안전하다.

### 일정 LLM 규칙과 데이터 소스는 한 세트로 맞춰야 한다

“API 블록에만 있는 행사만 쓴다”고 써 두면, 웹 검색·티켓 사이트에서 가져온 **실제로 유용한 데이터**를 모델이 스스로 배제할 수 있다. **허용 출처를 프롬프트에 나열**하고, 소스가 없을 때만 “공식 확인”으로 물러나게 하는 식으로 규칙과 파이프라인을 같이 조정해야 한다.

### 티켓 사이트 “크롤링”은 HTML만 보고 판단하면 안 된다

티켓링크류는 SEO용 얇은 셸 + 클라이언트 렌더링이라 **전통적 HTML 스크래핑이 빈손**인 경우가 많다. 반면 일부 경쟁사 모바일 페이지는 **SSR JSON(`__NEXT_DATA__`)**으로 동일 정보를 내려주므로, robots/이용약관을 준수하는 범위에서 **구조화된 스냅샷 파싱**이 비용 대비 효과가 크다. 배너(`hotItem`)까지 합치지 않으면 `interparkPlay` 소수 샘플만으로는 기간 필터 후 결과가 너무 적다.

### Waterbomb처럼 상위 배너에 없는 공연

인터파크 메인 배너에 올라오지 않으면 **같은 파이프라인만으로는 부족**할 수 있다. 여름 기간 웹 검색 보강, 공공 행사 API, K-pop 키워드 필터를 **병행**하는 설계가 현실적이다.

### 10.2 권장 개선 (숙박·요금·링크)

1. **문구 대신 데이터 제공 (권장)**  
   - `lodging` 질문이면 항상 Google Places 검색 (`has_places=True`).  
   - 위저드처럼 평점, `price_level`, `maps_url`을 카드로 표시 (이미 `api_places_search`·`wizard.js`에 있음).  
   - LLM은 「카드에 나온 호텔 중에서 고르세요」 정도만 말하게 유지.

2. **실시간 요금·예약은 아직 한계**  
   - Google Places `price_level`은 대략 구간(¥¥)이지 「오늘 12만 원」이 아님.  
   - 실제 예약·최신 요금은 네이버/야놀자/Booking API 연동 없이는 시스템이 대신 못 줌.  
   - 그때는 「확인하세요」 대신 **구체 링크 1개**(선택 호텔 Google Maps, 또는 지역 검색 URL)만 붙이는 편이 나음.

3. **환전소** — 인천공항·홍대 등 환전소 안내 기능 추가 예정(메모).

### 10.3 성능 — 병렬화 아이디어 (미적용/검토용)

- **변경 1 — `_search_places_for_itinerary` 내부 병렬화 (line ~649)**  
  - 에리어별 `search_by_text` 호출을 `ThreadPoolExecutor(max_workers=4)`로 병렬 실행.  
  - 예: 4개 에리어 직렬 4×1.5s → 병렬 최대 1.5s.

- **변경 2 — `route_and_answer` 데이터 수집 단계 병렬화 (line ~887)**  
  - RAG / Places / Aviation / itinerary Places / Sports 5개 작업을 `ThreadPoolExecutor(max_workers=5)`로 동시 실행.  
  - 결과는 각 `Future.result()`로 안전하게 수집.

※ 실제 저장소의 라인 번호는 브랜치·편집에 따라 변동될 수 있음.

### 10.4 일정·콘텐츠 소스 (메모)

- **콘서트·공연 등**, 여행 일정에 맞는 이벤트를 Ticketlink·Interpark에서 웹 스크래핑해 일정에 맞춰 추천 표시 — 한국관광공사 데이터셋, 전국공연행사정보표준데이터 API, 경기도 데이터셋 등과 병행 검토(요구사항 메모).  
  - (참고: 동일 날짜 보고 **§8.3**에 인터파크 모바일 SSR 파싱 구현 내역이 있음.)
