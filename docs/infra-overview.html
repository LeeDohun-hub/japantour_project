01 · Docker를 쓰는 이유
🐳
Docker란?
내 앱을 "상자(컨테이너)"에 담아서 어디서든 똑같이 실행되게 해주는 도구
💬 한 줄 요약 : "내 PC에서 되는데 서버에서 안 돼요" 문제를 없애주는 도구입니다.
  • 환경 통일 — 팀원 PC, 서버 모두 동일한 환경으로 실행됨
  • 빠른 배포 — 이미지 한 장만 있으면 어디서든 동일하게 띄움
  • 격리 — Spring Boot / MySQL / React가 서로 독립적인 컨테이너로 돌아감
  • docker-compose — 컨테이너 여러 개를 파일 하나로 한 번에 관리
📦
이 프로젝트에서 Docker 사용 구성
docker-compose.yml 한 파일로 3개 컨테이너를 한 번에 관리
# docker-compose 구성 이미지 ┌─────────────────────────────────────────┐ │ docker-compose up │ │ │ │ ┌──────────┐ ┌──────────┐ ┌───────┐ │ │ │ frontend │ │ backend │ │ mysql │ │ │ │ React │ │Spring Boot│ │ DB │ │ │ │:3000 │ │:8080 │ │:3306 │ │ │ └──────────┘ └──────────┘ └───────┘ │ └─────────────────────────────────────────┘
1
frontend 컨테이너

React(TypeScript) 빌드 결과물 서빙 · 포트 3000

2
backend 컨테이너

Spring Boot JAR 실행 · JWT 인증 · REST API 제공 · 포트 8080

3
mysql 컨테이너 (로컬 개발용)

개발 환경에서만 사용. 실제 배포 시엔 AWS RDS로 교체

02 · AWS를 쓰는 이유
☁️
AWS란?
Amazon이 제공하는 클라우드 서버 서비스 — 내 PC를 24시간 켜두지 않아도 됨
💬 한 줄 요약 : 내 앱을 인터넷 어디서나 접근 가능한 서버에 올려두는 것입니다.
🖥️
EC2
가상 서버 (리눅스 컴퓨터)
  • Docker 컨테이너를 실제 서버에서 실행
  • Spring Boot(API) + React(정적파일) 호스팅
  • 프리티어로 무료 사용 가능
🗄️
RDS
관리형 MySQL 데이터베이스
  • MySQL을 AWS가 관리해주는 서비스
  • 백업·보안·패치 자동화
  • EC2에서 직접 접속하여 사용
🪣
S3
파일 저장소 (영수증 이미지 저장용)
  • 영수증 이미지를 서버 디스크 대신 S3에 업로드·저장
  • DB에는 파일 경로(URL)만 저장 → receipt.file_path
  • 용량 걱정 없고 URL만으로 이미지 접근 가능
사용자 업로드 → S3 버킷 저장 ↓ URL 반환 DB receipt.file_path = "https://s3.ap-northeast-2.amazonaws.com/..."
03 · 전체 배포 흐름
🔄
코드 작성 → 배포 흐름
개발자 PC에서 AWS 서버까지
1
로컬 개발

VSCode에서 코드 작성 → docker-compose up으로 로컬에서 전체 앱 실행 및 테스트

2
Git Push

GitHub에 코드 푸시 (main 브랜치 기준 관리)

3
Docker 이미지 빌드

Dockerfile로 이미지 생성 → 필요 시 ECR(AWS 이미지 저장소)에 Push

4
EC2 서버에 배포

EC2 접속 → docker-compose up -d 실행 → 앱 가동

5
실제 서비스

EC2 IP 주소로 외부 접근 가능 · RDS는 EC2에서만 접근 · 영수증은 S3 저장
