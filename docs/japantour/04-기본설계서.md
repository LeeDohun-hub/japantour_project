## 2. 시스템 논리 구성

### 2.1 런타임(1차 제품)

```
┌─────────────────────────────────────┐
│           사용자 (브라우저)            │
└─────────────────┬───────────────────┘
                  │ HTTP
                  ▼
┌─────────────────────────────────────┐
│  Streamlit  app_japan_tour.py        │
│  · 세션 상태 (messages)              │
│  · 시스템 프롬프트 (일/한)           │
│  · OpenAI Chat Completions           │
└─────────────────┬───────────────────┘
                  │ HTTPS / JSON
                  ▼
┌─────────────────────────────────────┐
│         OpenAI API                   │
│  · gpt-4.1-mini (대화·번역)          │
└─────────────────────────────────────┘
```

### 2.2 오프라인 데이터 파이프라인

```
AI Hub 원본 (수동/aihubshell)
        ↓
data/raw/tour_knowledge.csv
        ↓  tour_preprocess.py (pandas)
data/processed/tour_knowledge.jsonl
        ↓ (향후)
임베딩·벡터 스토어·RAG 체인
```

## 3. 모듈·파일 책임

| 경로 | 책임 |
|------|------|
| `app_japan_tour.py` | UI, 세션, OpenAI 호출, 번역 호출, 프롬프트 구성 |
| `setup_data.py` | `data` 디렉터리 복사·zip·URL 다운로드 |
| `tour_preprocess.py` | CSV 검증·정제·JSONL 출력 |
| `requirements.txt` | Python 의존성 목록 |
| `src/config.py` | OpenAI·LangSmith 등 — **메인 Streamlit 앱은 직접 `os.getenv` 사용** |
| `src/chain/*`, `src/api/*` | 관광 분류·LLM 답변 체인(지식베이스 검색은 추후 연동) |
| `evaluation/scripts/*` | Ragas 평가 — 도메인 교체 전까지는 참고용 |

## 4. 화면·UI 설계 (Streamlit)

### 4.1 화면 구역

| 구역 | 구성 요소 |
|------|-----------|
| 메인 | 제목, 캡션, 채팅 이력, `st.chat_input` |
| 사이드바 | 사용법(일·한), 응답 언어 라디오, AIHUB 키 안내, 대화 리셋 버튼 |

### 4.2 상태 모델

| 키 | 타입(논리) | 설명 |
|----|-------------|------|
| `messages` | list | `role`(user/assistant), `content`, 선택 `translated_ko` |

### 4.3 처리 시퀀스 (메시지 입력 시)

1. 사용자 입력을 `messages`에 추가.  
2. `chat_with_openai`: 시스템 프롬프트 + 기존 user/assistant + 현재 user → 완성 API.  
3. 응답 언어가「日本語」이면 `translate_to_korean` 호출 후 UI에 번역 블록 표시.  
4. `messages`에 assistant 항목 저장(번역은 `translated_ko`, 다음 턴 프롬프트에는 원문 위주).

## 5. 외부 인터페이스

### 5.1 OpenAI

| 용도 | 모델(현행 코드) | 비고 |
|------|------------------|------|
| 대화 | `gpt-4.1-mini` | temperature 0.7 |
| 한국어 번역 | `gpt-4.1-mini` | temperature 0.2, 별도 system 지시 |

### 5.2 AI Hub (데이터 취득)

- `aihubshell` CLI, 환경 변수 `AIHUB_APIKEY`.  
- 상세 명령: `DATA_SETUP.md`.

## 6. 데이터 설계

### 6.1 디렉터리

```
data/
  raw/
    tour_knowledge.csv    # 입력 (권장 스키마는 DATA_PREPROCESSING.md)
  processed/
    tour_knowledge.jsonl  # 출력 (1 line = 1 object)
```

### 6.2 JSONL 레코드(논리)

전처리 스크립트는 CSV에 존재하는 컬럼만 직렬화한다. 최소 `question_ja`, `answer_ja`; 선택적으로 `id`, `category`, `area`, `answer_ko`.

## 7. 오류·예외 처리 (기본)

| 상황 | 동작 |
|------|------|
| `OPENAI_API_KEY` 없음 | 경고 표시, 채팅 시 API 오류 메시지 |
| `tour_knowledge.csv` 없음 | `FileNotFoundError` 및 안내 메시지 |
| 필수 컬럼 누락 | `ValueError` 및 누락 컬럼명 표시 |

## 9. 확장 로드맵 (기본 설계 수준)

| 단계 | 내용 |
|------|------|
| RAG-1 | `tour_knowledge.jsonl` 또는 벡터 DB를 `app_japan_tour.py` 응답 전에 검색에 연결 |
| RAG-2 | `tour_knowledge` 임베딩 검색을 `prepare_context`에 연결 |
| 평가 | `evaluation/`에 Japan Tour용 `test_dataset.json` 및 정답 세트 추가 |
| 배포 | Streamlit Community Cloud / 컨테이너 / 리버스 프록시 등 별도 아키텍처 설계 |
