# Japan Tour Project — 요구사항 정의서

## 1. 문서 목적

본서는 **japantour_project**의 업무·시스템 요구를 정의하여, 개발·데이터 준비·검수의 기준으로 삼는다.

---

## 2. 시스템 개요

| 항목 | 내용 |
|------|------|
| 시스템 명 | Japan Tour — 한국 여행 일본인 안내 챗봇 |
| 목적 | 방한 일본인 대상 관광 질의에 **일본어 또는 한국어**로 안내 응답 |
| 주요 형태 | 웹 브라우저에서 동작하는 **Streamlit** 단일 앱 + 로컬 데이터 파이프라인 |

---

## 3. 이해관계자·전제

- 개발자는 Python 가상환경 및 `.env`를 사용할 수 있다.  
- **OpenAI API** 사용이 가능하고 `OPENAI_API_KEY`를 보유한다.  
- 관광 말뭉치는 **AI Hub 이용약관·신청 절차**를 준수하여 확보한다.

---

## 4. 기능 요구사항

### 4.0 회원·프로필·추천(기획 / 차기)

| ID | 요구사항 | 상세 |
|----|----------|------|
| FR-P01 | 회원가입 | 사용자 식별·약관 동의 등(백엔드 연동 시) |
| FR-P02 | 고객정보 입력 | 성별, 성격, 취미, 고향, 한국에 대한 흥미, 여행 예산 |
| FR-P03 | 일정·숙박 입력 | 비행기 출발·도착 시간, 호텔 예약 유무, 귀국 시간 |
| FR-P04 | 관광지 추천 | **인천공항** 거점 거리순 **또는** **숙소** 거점 거리순(선택 또는 자동 규칙) |
| FR-P05 | 챗봇 연동 | 프로필·추천 결과를 시스템 프롬프트 또는 컨텍스트에 반영 |
| FR-P06 | 공항→숙소 교통 | 도착 공항·도착 시각·숙소(또는 예정 지역)를 입력받아 **가장 빠른**·**가장 저렴한**·**환승 최소** 중 사용자 기준(또는 병렬 비교)으로 교통 수단·경로를 안내; 실시간 API 사용 시 출처·갱신 시각 표기 |

※ 현행 필수 범위는 **4.1 이하**이며, FR-P01~P06은 제품 로드맵 기준 요구로 둔다.

### 4.1 챗봇 UI (`app_japan_tour.py`)

| ID | 요구사항 | 상세 |
|----|----------|------|
| FR-01 | 페이지 메타 | 제목·아이콘·wide 레이아웃 설정 |
| FR-02 | 이용 안내 | 사이드바에 일·한 예시 질문 표시 |
| FR-03 | 응답 언어 선택 | 라디오: **日本語** / **한국어** |
| FR-04 | 채팅 입력 | 일본어 또는 한국어 자유 입력 |
| FR-05 | 대화 표시 | 사용자·어시스턴트 메시지를 채팅 형태로 표시 |
| FR-06 | LLM 응답 | 선택 언어에 맞는 시스템 프롬프트로 **gpt-4.1-mini** 채팅 완성 호출 |
| FR-07 | 일본어 응답 시 번역 | 응답 언어가 일본어일 때, 동일 응답의 **한국어 번역**을 별도 블록으로 표시 |
| FR-08 | 대화 초기화 | 버튼으로 세션 메시지 초기화 후 화면 갱신 |
| FR-09 | 키 상태 표시 | `OPENAI_API_KEY` 미설정 시 경고, `AIHUB_APIKEY`는 선택 정보로 표시 |

### 4.2 데이터 복구 (`setup_data.py`)

| ID | 요구사항 | 상세 |
|----|----------|------|
| FR-10 | 소스 선택 | `--source-dir`, `--source-zip`, `--download-url` 중 **하나 필수** |
| FR-11 | 대상 경로 | `--data-dir`(기본 `./data`), zip 다운로드 경로 `--download-to` |
| FR-12 | 강제 갱신 | `--force` 시 기존 `data` 삭제 후 재구성 |

### 4.3 전처리 (`tour_preprocess.py`)

| ID | 요구사항 | 상세 |
|----|----------|------|
| FR-13 | 입력 파일 | `data/raw/tour_knowledge.csv` 존재 |
| FR-14 | 필수 컬럼 | `question_ja`, `answer_ja` |
| FR-15 | 선택 컬럼 | `id`, `category`, `area`, `answer_ko` — 있으면 JSONL에 포함 |
| FR-16 | 정제 | 필수 텍스트 공백 행 제거, 문자열 trim |
| FR-17 | 출력 | `data/processed/tour_knowledge.jsonl` (1행 1JSON) |

## 5. 데이터 요구사항

### 5.1 `tour_knowledge.csv` (권장 스키마)

`DATA_PREPROCESSING.md`와 동일하게 다음을 권장한다.

| 컬럼 | 필수 | 설명 |
|------|------|------|
| `question_ja` | 예 | 일본어 질문 |
| `answer_ja` | 예 | 일본어 답변 |
| `id` | 선택 | 없으면 전처리 시 인덱스 기반 생성 |
| `category` | 선택 | nature, culture, food 등 |
| `area` | 선택 | 지역·도시 |
| `answer_ko` | 선택 | 한국어 답변 |

### 5.2 AI Hub 연계

- 데이터셋 식별자·다운로드 절차는 `DATA_SETUP.md`를 따른다.  
- 원본 형식은 데이터셋마다 다르므로, **프로젝트 표준 CSV**로의 변환은 수동 또는 별도 스크립트로 수행한다.

## 6. 비기능 요구사항

### 6.1 보안

- API 키·개인정보를 소스·Git에 넣지 않는다.  
- `.env`는 `.gitignore` 대상으로 유지한다.

### 6.2 가용성·운영

- Streamlit은 단일 프로세스 기준; 동시 사용자 다수 시 **별도 배포 설계**가 필요할 수 있다(본 문서 범위 외).

### 6.3 성능(가이드)

- OpenAI API 레이트·지연에 의존; UI에서 생성 중 **스피너** 표시.

### 6.4 유지보수

- 의존성은 `requirements.txt`로 고정한다.  
- 데이터 흐름은 `DATA_PREPROCESSING.md` 다이어그램과 본서를 기준으로 한다.

## 8. 제외 요구(명시적 비범위)

- `src/chain`은 **Streamlit 메인 앱과 별도**의 LangChain 평가·실험 경로로 둔다.
