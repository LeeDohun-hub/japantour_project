# Japan Tour Project — 개발 환경

## 1. 개요

본 프로젝트는 **방한 일본인 관광객**을 위한 한국 여행 안내 챗봇과, AI Hub 관광 일본어 말뭉치 기반 **데이터 파이프라인**을 포함합니다. 저장소에 `data/`는 포함되지 않으며, 클론 후 별도 준비가 필요합니다.

---

## 2. 하드웨어·OS

| 항목 | 권장 |
|------|------|
| OS | Windows 10/11 (PowerShell), 또는 WSL / Git Bash (`aihubshell` 사용 시 bash 권장) |
| 메모리 | Python·Streamlit·pandas 동시 사용 시 **8GB 이상** 권장 |
| 디스크 | AI Hub 원본·압축 해제본은 데이터셋 크기에 따라 **수 GB 이상** 여유 권장 |

---

## 3. 런타임·언어

| 항목 | 버전 |
|------|------|
| Python | `requirements.txt` 기준 호환 버전(예: **3.10 이상** 권장, 팀 표준에 맞출 것) |
| 패키지 관리 | `pip` + 가상환경(`venv` 등) 권장 |

---

## 4. IDE·도구

| 도구 | 용도 |
|------|------|
| VS Code / Cursor | 코드 편집, 터미널 통합 |
| Git | 버전 관리(원격: GitHub 등) |
| (선택) WSL 또는 Git Bash | AI Hub `aihubshell` 실행 환경 |

※ 본 저장소의 메인 앱은 **Java/Tomcat이 아닌 Python + Streamlit**입니다.

---

## 5. 주요 의존성 (`requirements.txt` 요약)

| 분류 | 패키지 | 용도 |
|------|--------|------|
| UI | `streamlit` | 챗봇 웹 UI (`app_japan_tour.py`) |
| LLM | `openai`, `langchain`, `langchain-openai`, `langchain-core` | OpenAI API·체인 실험 |
| 공통 | `python-dotenv`, `requests` | 환경 변수, HTTP |
| 데이터 | `pandas` | CSV 전처리 (`tour_preprocess.py`) |
| 평가(선택) | `ragas`, `datasets`, `tqdm`, `colorama` | RAG 품질 평가 스크립트(`evaluation/`) |

설치:

```bash
pip install -r requirements.txt
```

---

## 6. 환경 변수 (`.env`)

루트에 **`.env.example`**을 복사해 `.env`를 만든 뒤 값을 채웁니다. (`README.md` 절차 참고)

| 변수명 | 필수 | 설명 |
|--------|------|------|
| `OPENAI_API_KEY` | **예** (챗봇 동작) | OpenAI API 키 |
| `AIHUB_APIKEY` | 아니오 | AI Hub 데이터 다운로드(`aihubshell`) 시 사용 |
| `LANGSMITH_API_KEY` | 아니오 | `src/` LangChain 실험 시 추적용(설정된 경우) |
| `LANGCHAIN_PROJECT` | 아니오 | LangSmith 프로젝트명(미설정 시 `japantour`) |

비밀값은 **저장소에 커밋하지 않습니다.**

---

## 7. 데이터 디렉터리 복구

Git에는 `data/`가 없습니다. 다음 중 하나로 준비합니다.

| 방법 | 명령/참고 |
|------|-----------|
| 로컬 폴더 | `python setup_data.py --source-dir "<경로>" --force` |
| 로컬 zip | `python setup_data.py --source-zip "<경로.zip>" --force` |
| URL zip | `python setup_data.py --download-url "<URL>" --force` |

AI Hub에서 받은 경우: `DATA_SETUP.md`의 `aihubshell` 절차 후, 원본을 `data/raw/`에 맞게 정리합니다.

---

## 8. 전처리·실행

| 단계 | 명령/파일 |
|------|-----------|
| 원본 CSV | `data/raw/tour_knowledge.csv` (스키마는 `DATA_PREPROCESSING.md`) |
| JSONL 변환 | `python tour_preprocess.py` → `data/processed/tour_knowledge.jsonl` |
| 챗봇 실행 | `streamlit run app_japan_tour.py` |

---

## 9. 기타 모듈 (`src/`, `evaluation/`)

| 경로 | 설명 |
|------|------|
| `src/chain/rag_chain.py` 등 | 관광 질문 분류 + LLM 답변(지식베이스 검색은 추후 연동). 메인 챗봇(`app_japan_tour.py`)과는 별도 파이프라인. |
| `evaluation/` | Ragas 기반 평가 스크립트·샘플 JSON. Japan Tour용 질문·정답 세트로 교체하면 그대로 활용 가능. |

팀 내에서는 “제품 1차 = Streamlit 여행 챗봇 + 데이터 파이프라인”으로 범위를 고정하고, RAG/평가는 2차 과제로 관리하는 것을 권장합니다.

---

## 10. 외부 서비스·제약
