## 1. プロフィール連携型チャット

- 旅行者プロフィール（性別、性格、趣味、出身地、韓国への関心、予算、フライト出発・到着、ホテル予約の有無、帰国時刻等）に基づく**パーソナライズ案内**。
- テキストに加え**画像認識**（看板・メニュー等）による直感的応答の設計。

## 2. 旅行タイプ診断（MBTI 等）

- タイプ別の案内・プロンプト反映。
- 診断のたびに LLM が**新しい質問セット**を生成する設計（同じ質問の繰り返しを避ける）。

## 3. 対話・プロフィール連動コンテンツ推薦

- TF-IDF 類似度、または**埋め込み・RAG**による推薦。
- 相談内容とプロフィールから観光知識コンテンツを自動推薦し、情報探索と次アクションを促す。

## 4. 旅行サマリー PDF

- 希望日・セッションの対話を要約した**ダウンロード可能な PDF**。
- 要約、注意事項（休業・終電・予約等）、次の旅行提案などを含める想定。

## 5. 空港 → 宿泊（初動線）

- 到着情報と宿泊位置から、**最速**・**最安**・**乗り換え最少**等の交通案内（または比較）。
- リアルタイム API 利用時は**出典・基準時刻**の表示。

## 6. 観光地推薦ロジック（企画）

- **仁川空港**基準の距離順、または**宿泊（拠点）**基準の距離順。

## 7. モデル・パイプライン（目標）

- テキスト: Qwen 系等 / マルチモーダル: GPT-4o 等の役割分担。
- RAG: `text-embedding-3-small` + FAISS 等のベクトル検索。
- 質問タイプ分類（行動補正 / 情報探索 / 感情共感等）とタイプ別プロンプト。
- 長期記憶: 直近 N ターン要約を ChromaDB 等にユーザー ID 単位で保存・検索。

## 8. デプロイ（目標）

- Django を Docker 化し、AWS（EC2・S3・RDS 等）と連携する構成の記述がある場合、**現行リポジトリの必須構成ではない**。詳細は上記 `.docx` およびルート `README.md` を参照。
