# Japan Tour Project（要件定義書）

________________________________________

## 1. はじめに

### 1.1 要件定義書の目的

本要件定義書は、**訪韓日本人観光客向けの韓国旅行案内チャットボット**として開発する「Japan Tour Project」について、業務要件およびシステム要件を明確化し、以降の基本設計・詳細設計・実装の指針とすることを目的とする。

### 1.2 対象者

- 開発担当者
- 研修講師・レビュー担当者
-	開発リーダー（進捗・成果物管理）

### 1.3 開発前提条件

- 開発目的：訪韓日本人観光客向けの旅行案内サービスの構築および学習
- 開発体制：少人数チーム
- 利用言語：日本語・韓国語
- 外部サービス：OpenAI API、Google Maps Platform、AI Hub
- データセット：AI Hub「生成型AI K-Culture 観光コンテンツ特化 日本語コーパス」等

________________________________________

## 2. システム概要

### 2.1 システム名称

Japan Tour Project（韓国旅行・日本人向け案内チャットボット）

### 2.2 システムの目的

- 訪韓日本人観光客が**日本語または韓国語**で韓国旅行の質問を行えるようにする
- 観光地・グルメ・交通・文化マナー・季節別服装等を AI が案内する
- 現在地周辺の観光地・カフェを **Google Places API** で推薦する
- AI Hub の観光日本語コーパスをもとに **Q&A 知識ベース（`tour_knowledge`）** を構築し、将来的な RAG 連携の土台とする

### 2.3 想定利用環境

| 区分 | 内容 |
|------|------|
| 利用者（観光客） | スマートフォン／PC の Web ブラウザ |
| 管理者（運営） | PC の Web ブラウザ |
| サーバ | Python + Streamlit（メイン）／Python + Django（任意の HTML フロント連携時） |
| 外部 API | OpenAI API、Google Maps Platform（Places API） |

________________________________________

## 3. 業務要件

### 3.1 業務対象

- 訪韓日本人観光客に対する旅行案内業務
- 観光知識データ（AI Hub）の取得・整備業務
- データ前処理および Q&A 知識ベースの維持業務

### 3.2 業務フロー

1. 利用者がブラウザで Japan Tour を開く
2. 応答言語（日本語／韓国語）を選択する
3. 観光・交通・グルメ等の質問を入力する
4. システムが OpenAI API に問い合わせて回答を生成する
5. 日本語回答の場合は韓国語訳を併記する
6. 必要に応じて現在地または座標を入力し、周辺の観光地・カフェを取得する
7. 運営側は AI Hub データを取得・整形し、`data/raw/tour_knowledge.csv` を維持する
8. 前処理スクリプトで `data/processed/tour_knowledge.jsonl` を生成し、将来的に RAG で活用する

## 4. 利用者要件

### 4.1 利用者区分

| 利用者 | 概要 |
|--------|------|
| 観光客（一般利用者） | チャットボットに質問し、案内・推薦を受け取る |
| 運営担当者 | データ準備、環境変数管理、デプロイ運用を行う |

### 4.2 権限概要

- 観光客：チャット入力、応答言語切り替え、対話リセット、現在地周辺検索の利用が可能
- 運営担当者：API キーおよび `.env` の管理、データ取得・前処理、サーバ起動・停止が可能

## 5. 機能要件

### 5.1 認証機能

- 一般利用者向けのログイン認証は本範囲では設けない（公開型チャット）
- 運営側は OS および `.env` ファイルによって API キーを保護する

### 5.2 チャット機能（利用者向け）

- 日本語または韓国語による質問入力
- 応答言語の選択（日本語／韓国語）
- AI（OpenAI `gpt-4.1-mini`）による旅行案内応答
- 日本語応答時の韓国語訳併記
- 対話履歴の保持と画面表示
- 対話のリセット

### 5.3 周辺推薦機能（利用者向け）

- ブラウザ位置情報または手動入力座標からの現在地取得
- 検索半径（メートル）の指定
- 観光地（tourist_attraction）の取得・表示
- カフェ（cafe）の取得・表示
- 評価・レビュー数・距離・営業状況の表示
- Google Maps へのリンク表示

### 5.4 データ復元機能（運営向け）

- `setup_data.py` によるローカルディレクトリからの復元（`--source-dir`）
- ローカル zip からの展開（`--source-zip`）
- URL からのダウンロード＋展開（`--download-url`）
- 既存 `data/` の強制再構成（`--force`）

### 5.5 データ前処理機能（運営向け）

- `tour_preprocess.py` による `data/raw/tour_knowledge.csv` の読み込み
- 必須列（`question_ja`, `answer_ja`）の検証
- 任意列（`id`, `category`, `area`, `answer_ko`）の保持
- 文字列の前後空白除去および空必須行の除去
- `data/processed/tour_knowledge.jsonl` への出力（1 行 1 JSON）

### 5.6 任意 UI 機能（Django 連携）

- `frontend/home.html` および `frontend/chat.html` の配信
- `/api/health/` による稼働確認
- `/api/chat/` によるチャット応答 API

## 6. 非機能要件

### 6.1 性能要件

- 想定同時利用者数：少数（教育・デモ用途）
- 応答時間：OpenAI API および Google Places API のレスポンスに依存
- 生成中はスピナー等で待機状態を表示する

### 6.2 セキュリティ要件

- API キー（`OPENAI_API_KEY`、`GOOGLE_MAPS_API_KEY`、`AIHUB_APIKEY`）はソースコードおよび Git に含めない
- `.env` および `data/` は `.gitignore` の対象とする
- 入力検証：Django `/api/chat/` ではメッセージ長・履歴件数・応答言語値を検証する

### 6.3 可用性・保守性

- 依存関係は `requirements.txt` で固定する
- データフローおよびスキーマは `DATA_PREPROCESSING.md` を正とする
- Streamlit は単一プロセス前提とし、同時多数利用には別途デプロイ設計が必要

## 8. データ要件（概要）

主な管理データ：

- `tour_knowledge.csv`（原本 Q&A テーブル）

  - 任意列：`id`、`category`、`area`、`answer_ko`
